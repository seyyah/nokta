# Customer-as-Developer Use Case

Track B focuses on a customer who does not write code but still drives implementation. The customer uses the audit widget to mark a missing behavior, not just a visual bug: "show me how my note becomes a developer task." That report becomes a structured feature request with visual ground truth, screen name, selection coordinates, and a natural-language intent.

The new use case is a mobile feedback loop where a product owner can create a tiny implementation brief while staying inside the app. The forge agent reads the Markdown report, maps it to the screen, adds one bounded behavior, verifies it, and logs the result. The customer has effectively authored the next code change without touching the codebase.
